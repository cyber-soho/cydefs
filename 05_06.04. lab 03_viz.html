Step 1

Take a snapshot of every virtual machine

Open VirtualBox, select FS-01, go to the Snapshots tab, choose Take, name it before-LAB03. Repeat for WS-WIN-01 (and WS-LIN-01 if you will change it).

Why: A snapshot is the only thing that makes every later step safe: if a change breaks the machine you return to this exact state in seconds instead of rebuilding it.

VBoxManage snapshot "FS-01" take "before-LAB03" --description "state before hardening" VBoxManage snapshot "WS-WIN-01" take "before-LAB03"

You are done when: Both machines show a snapshot named before-LAB03 under Current State.

version noteDrawn from Oracle VirtualBox 7.2.16 (18 August 2026). A later 7.2.x or 7.3 release may move or rename buttons; the path stays machine → Snapshots → Take. With QEMU/KVM the equivalent is virsh snapshot-create-as, and Proxmox VE has a Snapshots tab per virtual machine.

Step 2

Measure the attack surface of FS-01

List every listening endpoint, save the output as your BEFORE evidence, then let the course script compare the list with the role of the host.

Why: Hardening is only credible when it is measured. Eight listeners before and two after is a number you can put in the manual; "I hardened it" is not.

sudo ss -tulpn sudo ss -tulpn > ss_before_FS-01.txt python3 nm_attack_surface.py file-server --host FS-01 --from-file ss_before_FS-01.txt

You are done when: You have ss_before_FS-01.txt and a printed keep/disable decision for each endpoint.

version notess comes from iproute2 and its columns are stable across Ubuntu 24.04 and 26.04; a future release may add columns, so read by header, not by position. On Windows the equivalent listing is netstat -ano or Get-NetTCPConnection -State Listen.

Step 3

Disable what the role does not need

Switch off the services that a file server never uses, remove the software that nothing needs, then take the AFTER listing.

Why: Every service that is not running is a door that cannot be opened — not by a mistake, not by an attacker, not by malware.

sudo systemctl disable --now avahi-daemon sudo systemctl disable --now cups sudo systemctl disable --now rpcbind sudo systemctl disable --now postfix sudo apt purge -y mysql-server sudo ss -tulpn > ss_after_FS-01.txt

You are done when: Only tcp/22 and tcp/445 are still listening, and the shared folder still opens from WS-WIN-01.

version noteUbuntu 26.04 LTS ships systemd 259; the disable --now syntax is unchanged since 24.04. Unit names differ between distributions (for example cups.service plus cups.socket on the Red Hat family) — check with systemctl list-units --type=service before you disable anything.

Step 4a

Install and test your key first

Create a key pair on the administrator workstation, copy the public key to the server, and confirm that the key login works — while your current session stays open.

Why: The next step switches password login off. If the key does not work yet, that step locks you out of your own server.

ssh-keygen -t ed25519 -C "admin@northmaple" ssh-copy-id admin@192.168.30.10 ssh admin@192.168.30.10

You are done when: A second terminal connects to FS-01 without being asked for a password.

version noteOpenSSH behaviour is stable; recent versions already default to ed25519 keys, so -t ed25519 is explicit rather than required. If your college images disable ssh-copy-id, append the contents of ~/.ssh/id_ed25519.pub to ~/.ssh/authorized_keys on the server by hand.

Step 4b

The four SSH baseline values

Edit /etc/ssh/sshd_config, set the four values, validate the file, restart the service, then print the effective configuration as evidence.

Why: SSH is the administrative door of every Linux host in the company. These four values remove root logins, password guessing and an unused forwarding feature in one edit.

sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak-$(date +%F) sudo nano /etc/ssh/sshd_config sudo sshd -t sudo systemctl restart ssh sudo sshd -T | grep -Ei 'permitrootlogin|passwordauthentication|maxauthtries|x11forwarding'

You are done when: sshd -T prints: permitrootlogin no · passwordauthentication no · maxauthtries 3 · x11forwarding no.

version noteOn Ubuntu 24.04 and 26.04 the SSH server is socket-activated: systemctl restart ssh applies changes in sshd_config, but a change of Port or ListenAddress must be made in ssh.socket. On the Red Hat family the service is named sshd.

Step 5

Updates and accounts

Install the pending corrections, switch on automatic security updates, and confirm that no account has an empty password.

Why: A hardened host with a two-month-old kernel is not hardened. Automatic security updates are the one measure that keeps working when nobody is watching.

sudo apt update && sudo apt upgrade -y sudo apt install -y unattended-upgrades sudo dpkg-reconfigure --priority=low unattended-upgrades cat /etc/apt/apt.conf.d/20auto-upgrades sudo awk -F: '($2==""){print $1}' /etc/shadow

You are done when: 20auto-upgrades shows "1" twice, and the last command prints nothing at all.

version noteUbuntu 26.04 LTS uses Rust-based sudo-rs and coreutils — the syntax above is unchanged. On Fedora, RHEL, Rocky or AlmaLinux the equivalent of unattended-upgrades is dnf-automatic.

Step 6

The ten Windows items

Run the audit script with no option (BEFORE), preview the changes with -WhatIf, then apply them and let the script re-test each item (AFTER).

Why: The ten items are the account, service, update and policy settings that Windows leaves open for compatibility. The script produces both states, so the evidence is a by-product of running it.

Set-ExecutionPolicy -Scope Process Bypass -Force .\nm_win_hardening_check.ps1 .\nm_win_hardening_check.ps1 -Apply -WhatIf .\nm_win_hardening_check.ps1 -Apply

You are done when: A CSV file with a BEFORE and an AFTER column for W01 to W10, and the two manual items done by hand.

version noteCaptured on Windows 11 25H2 (September 2026 update, build 26200.9445). A later feature update may restyle the console window; the NetSecurity and LocalAccounts cmdlets used by the script are unchanged. Note that 24H2 Home and Pro stop receiving updates on 13 October 2026 — item W09 will fail on 24H2 after that date whatever you do, so move to 25H2.

Step 7

Score the host against a baseline

Compare the host with a ten-item baseline, read the Level 1 and Level 2 scores, and write one sentence of justification for anything you leave failed on purpose.

Why: A score turns your work into a sentence the grading checklist can read: "Level 1 at 100 %, Level 2 at 89 %, one documented exception, one item to fix."

python3 nm_baseline_audit.py --host WS-WIN-01 sudo lynis audit system # optional second opinion, laboratory only

You are done when: Two scores, every exception justified in writing, and a short to-do list of items still failing.

version noteThe CIS Benchmarks are revised several times a year and a benchmark exists per operating system version — download the current PDF for your version, because recommendation numbers shift between editions. Lynis and OpenSCAP update their checks independently.

Step 8

Write the rule table before typing anything

For each host, write one row per service the role really offers: rule name, port, the smallest source that needs it, and one sentence saying why.

Why: The source column is what makes a rule set secure. A table written first also prevents the most common accident: enabling a firewall without a rule for your own access.

# sheet 05 and 06 of the reference workbook, or: 420-D03-AB_C05-C06_firewall_rules_by_role.csv

You are done when: A table with no empty justification and no source wider than the role needs.

version noteThe addresses shown follow the course VM Planning Kit (user zone 192.168.20.0/24, server zone 192.168.30.0/24). If your own laboratory uses different networks, change the values everywhere — the reasoning does not change.

Step 9

Apply the rules in the safe order (Linux)

From the console window of the machine: management rule first, then the default policies, then the role rule, then logging, and only then enable the firewall.

Why: Every element of the order exists to prevent one accident. The management rule first prevents the lock-out; logging before enabling captures the very first dropped packet.

sudo ufw status numbered > ufw_before_$(date +%F).txt ./nm_ufw_fileserver.sh # dry run: prints, changes nothing sudo ./nm_ufw_fileserver.sh --apply sudo ufw status verbose > ufw_after_$(date +%F).txt

You are done when: ufw status shows: active, deny incoming, allow outgoing, and exactly your two scoped rules.

version noteUFW wording is stable across Ubuntu 24.04 and 26.04. On the Red Hat family use firewalld with --permanent followed by --reload (the full command list is in the lab document); rules added without --permanent disappear at the next restart.

Step 9b

The same order on Windows

Print the rule table of the role, then apply it: all three profiles on with inbound blocked by default, logging on, and one scoped rule per row.

Why: A Windows workstation needs almost no inbound rule. What it does need is the same default deny, on all three profiles, so the machine keeps its rules on any network.

.\nm_role_firewall_rules.ps1 -Role Workstation .\nm_role_firewall_rules.ps1 -Role Workstation -Apply Get-NetFirewallRule -DisplayName 'NM-*' | Format-Table DisplayName, Action, Profile

You are done when: Domain, Private and Public all show Enabled True / Block inbound, and your NM- rules exist.

version noteSame version caveat as Step 6: captured on Windows 11 25H2. The graphical console wf.msc and the PowerShell cmdlets have been stable for several releases, but a feature update can change window styling. See the official Microsoft Learn page for the current wording.

Step 10

Prove that every rule works

Run one test from an allowed machine and one from a denied machine for every rule, record the observed outcome, and treat a FAIL as a task, not as an error to hide.

Why: A rule that exists is not a rule that works. Only the negative test — from a machine that must be refused — reveals a rule that was scoped too widely.

nc -zv 192.168.30.10 445 Test-NetConnection -ComputerName 192.168.30.10 -Port 445 python3 nm_rule_validation.py --from WS-WIN-01 sudo tail /var/log/ufw.log

You are done when: Every row of the matrix has an observed outcome, and the pass rate reaches 100 % after your fixes.

version noteTest-NetConnection exists in Windows PowerShell 5.1, which ships with Windows 11; in PowerShell 7 the equivalent is Test-Connection -TargetName <host> -TcpPort <port>. Nmap may replace netcat — against your own virtual machines only.

Evidence

What you keep, and how you name it

Collect the outputs and screenshots into one folder per kind, with names that say which item they prove and on which host.

Why: The grader reads your evidence, not your memory. A file named ss_after_FS-01.txt proves a step; a file named Screenshot_47.png proves nothing.

LAB03_LASTNAME_Firstname/ ├─ LAB03_report_LASTNAME_Firstname.pdf ├─ workbook/ 420-D03-AB_C06_LAB03_Workbook_LASTNAME_Firstname.xlsx ├─ evidence/ ss_*, ufw_*, sshd_T_*, *.csv └─ screenshots/ W03_before_WS-WIN-01.png, L01_after_FS-01.png

You are done when: Every checklist row has both states, and no screenshot shows real names, real e-mails or real credentials.

version noteNaming and structure come from the course documentation standard, so they do not depend on any software version. Any screenshot tool works — Flameshot, ShareX, GNOME Screenshot or the Windows Snipping Tool.
