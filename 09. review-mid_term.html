A.3What cyber defense means, and why one wall is not enough

Cyber defense has two goals. A defensible infrastructure is one whose design makes defending it possible. A network where every machine reaches every other machine, where nobody knows what is connected, and where one password opens everything cannot be defended, however good the defender is. A cyber-resilient business keeps running during an attack and recovers after it. Resilience does not promise that nothing bad happens. It assumes that something bad will happen and asks whether the company can still work afterwards.

Three words are kept apart. A method is the approach ("divide the network into zones"). A technique is how the approach is carried out ("put the public web server in its own zone with its own firewall rules"). A tool is the software that does it (pfSense, OPNsense, Windows Defender Firewall, Snort). Tools change every two years; methods change very little.

Defence in depth means that several simple, imperfect protections are layered, and the company does not depend on one strong protection. The numbers of the class show why. One control that stops 90% of attempts lets 100 attempts in 1,000 through. Five ordinary controls that each stop 70% let only 0.3 × 0.3 × 0.3 × 0.3 × 0.3 = 0.00243 through, which is about 2 attempts in 1,000. The layers also fail for different reasons: a firewall rule and a backup do not fail for the same cause on the same day.

The example of the class: at 08:40 on a Tuesday, an accountant opens an attachment that she should not have opened. Without layers, her account is a local administrator, it reaches the whole file server, and no separate backup exists; by 09:15 the client records are encrypted. With layers, the first two layers miss the attachment, but her account is not an administrator, she reaches only the folder she needs, the intrusion detection system records unusual traffic at 08:41, and the backup of 02:00 is on storage that her account cannot write to. The same mistake now costs one restored folder.

A.4Where the company touches the outside world

Term Meaning
Asset Any machine, service or account that the company owns and must protect.
Entry point (perimeter element) A place where traffic from outside is allowed to reach an asset.
Attack surface The complete list of entry points, not only the ones that look dangerous.
Attack vector The route that somebody takes through an entry point.

An entry point is not a mistake. NorthMaple needs a public website, e-mail and remote access to do business. The work of the defender is to know exactly how many entry points exist and to put the strongest controls on them. For each system the defender asks one yes-or-no question: "Can somebody outside the company reach this?" The question is not "Is it important?" The file server is the most important asset of the company, and it is not an entry point.

NorthMaple has seven systems and four entry points: the company website, the mail relay, the remote access through the VPN (Virtual Private Network), and the guest Wi-Fi radio. The guest Wi-Fi is the one that people forget, because a radio signal does not stop at the wall of the office. The client file server, the staff workstations and the backup target are internal. The attack surface is therefore 4 entry points out of 7 systems.

The handout also reports the situation of 2025 and 2026: attackers automate the search for targets and the first contact with AI (Artificial Intelligence). It cites Microsoft security researchers (Microsoft Security Blog — https://www.microsoft.com/en-us/security/blog/), Palo Alto Networks Unit 42 (Unit 42 — https://unit42.paloaltonetworks.com/), which reported that scanning for a new vulnerability can start about fifteen minutes after its announcement, and KnowBe4 (KnowBe4 — https://www.knowbe4.com/), which reported that about 85.8% of phishing attacks in a recent six-month period were driven by AI. A.5Cutting the network into zones

On a flat network, every machine can talk to every other machine. The security of the whole company then equals the security of its weakest machine. Zoning corrects this: the network is divided into groups of systems that need similar protection, and the traffic that crosses from one group to another is controlled.

Zone Trust level What is placed there Why it is separate
Internet 0 Everybody else in the world The company controls nothing there.
DMZ (Demilitarized Zone) 1 The public web server Strangers connect to it all day, so it is the machine most likely to be compromised.
Guest Wi-Fi 1 Phones and laptops of visitors The company does not manage these devices.
User zone 2 Staff workstations and staff Wi-Fi Managed machines and known people.
Server zone 3 File server, client records, backups The data that the company must protect first.

A DMZ is a zone for systems that must be reachable from the Internet, arranged so that a compromise of those systems reaches nothing else. The designer assumes that the public server will be compromised one day and places it where this is survivable.

The rule of the zoning table has three parts: every system sits in exactly one zone; every allowed flow between zones has a written justification; anything that is not in the table is denied. A network that allows everything except a list of bad things is never finished, because that list has no end. A network that denies everything except a written list of good things is finished on the day the list is written.

The public website goes into the DMZ with two rules. The Internet may reach it on HTTPS (Hypertext Transfer Protocol Secure) port 443, because this is the business need. The DMZ may not reach the Server zone at all, with no exception. Placing the website in the Server zone puts the most exposed machine next to the client records. Placing it in the User zone gives strangers a permitted path to the place where the staff work.

A.6Trust levels, and the tools that watch the border

Each zone receives a number from 0 to 3 that records how much control the company has over what happens inside it. For every flow, compare the number of the source with the number of the destination.

Direction Meaning Decision
Down in trust, for example User 2 to Internet 0 Normal work Allowed and written down.
Up in trust, for example Internet 0 to DMZ (Demilitarized Zone) 1 The direction in which attacks travel Written down, justified, narrowed to one service and inspected, or denied.
Same level, for example DMZ 1 and Guest 1 Two zones that were separated on purpose Needs a very strong reason, or it does not exist.

The four requests of the class show the method. Internet to DMZ on HTTPS (Hypertext Transfer Protocol Secure) 443 climbs and is approved, because it is justified, narrowed and inspected. User to Internet descends and is approved. DMZ to Server "just for the client portal" climbs two levels from the most exposed machine to the most protected zone and is denied; if the portal needs data, a copy that contains only what it needs is brought to it in a controlled way. Guest to User "to print" climbs and is denied, or replaced by one tightly scoped path to one printer. The direction tells you where to look; the justification tells you what to decide.

A.7A prioritized checklist, a team that watches, and proof that it holds

The CIS (Center for Internet Security) Critical Security Controls are published free by the Center for Internet Security and answer the question "out of everything, what do I do first?". Version 8.1 contains 18 controls made of 153 safeguards. A safeguard is one specific, measurable action. The safeguards are sorted into three Implementation Groups. Implementation Group 1, called essential cyber hygiene, has 56 safeguards and is aimed at small organizations with limited expertise, such as NorthMaple. The first six controls, in plain words: know your devices, know your software, know your data, configure securely, manage accounts, control access.

A SOC (Security Operations Center) is the team that watches continuously and acts when something is found. It is a function, not a room, and a small firm usually buys it instead of building it. Its loop has five steps: collect the logs in one place, detect something unusual, triage (a person decides whether it is real), respond by containing and restoring, and improve by turning the finding into a new rule. Collecting works only if the network has a shape: on a flat network everything looks normal, because everything already talks to everything. Zones create expectations, and detection consists in noticing broken expectations. In 2026, AI (Artificial Intelligence) does the first reading of the alerts in triage; the judgement stays with the human.

Resilience is never assessed with the question "are we secure?", because that question has no answer. It is assessed by naming one scenario and answering four questions: which defence layer responds, does the business keep operating, how long until normal service returns, and what evidence proves the answer. Chapter 7 of the Final Project contains ten scenarios, each with the layers that respond, a verdict (withstands, partly, does not withstand) and one plain sentence of justification. "Does not withstand" is a valid, full-marks answer when it is true and you say what you would add.

The hygiene example of NorthMaple replaces "are we secure?" with six questions that do have an answer. The result is four "yes" out of six. The two "no" answers are the list of every piece of software, and the default passwords (nobody has checked the wireless access point since it was installed). These two items become the work plan.

B.1.1Privilege and access management: who may do what, on which system

Access control is the set of rules and mechanisms that decide whether a subject (a user account, a service, a program) may perform an operation (read, write, execute, delete, change permissions) on an object (a file, a folder, a database, a network device, a service). Every decision has exactly these three parts, and cyber defense starts by writing the decisions down before any system is configured.

Term Meaning
Identity The digital representation of a person or a program. A user account with a unique identifier: a SID (Security Identifier) on Windows, a UID (User Identifier) on Linux.
Authentication Verifies that the entity that uses an identity is the one it claims to be (password, hardware key, one-time code).
Authorization Decides, after a successful authentication, what the identity may do. Permissions and privileges apply here.
Accounting (auditing) Records what the identity actually did, so that access can be reviewed later.

The three processes form the AAA (Authentication, Authorization, Accounting) model, in this order. A permission is a right attached to an object ("the group accountants may modify the folder ClientRecords"). A privilege is a right attached to an identity and valid on the whole system ("the account g.lopez may install software"). Windows calls privileges user rights; Linux grants most of them through the root account, reached with sudo.

Privilege and access management, called IAM (Identity and Access Management) in the industry, has five steps: decide which roles exist; decide which permissions and privileges each role needs on each system; create the identities and groups; review the result at fixed intervals; remove access as soon as it is no longer needed. The written result of the second step is the access matrix: one row per role, one column per system, and in each cell the highest privilege level of the role. The course uses four levels: NONE, READ, USE (read and write the data of the role) and ADMIN (change the configuration of the system itself). The rule checked at NorthMaple: only the IT (Information Technology) administrator holds ADMIN on the firewall, the web server, the file server and the VPN (Virtual Private Network) gateway.

Three models organize the decision. With DAC (Discretionary Access Control), the owner of the object decides; it is the default model of NTFS (New Technology File System) permissions and of Linux file permissions. With MAC (Mandatory Access Control), a central policy compares security labels (SELinux and AppArmor on Linux); awareness level only. With RBAC (Role-Based Access Control), permissions are attached to roles, roles are implemented as groups, and an identity receives access by being placed in a group; every laboratory of the course uses this model.

Access control is a layer of defence in depth: it limits what an attacker can do after another defence has failed. The Center for Internet Security dedicates Control 5 (Account Management) and Control 6 (Access Control Management) to it, and the definitions follow the glossary of NIST (National Institute of Standards and Technology).

B.1.2The principles of least privilege and need-to-know access control

Least privilege: every identity (user, service, program) holds only the permissions and privileges strictly required for its assigned task, for the shortest time required, and nothing more. NIST (National Institute of Standards and Technology) states it as control AC-6 of Special Publication 800-53. Three practical consequences: daily work is never done with an administrative account; a permission is granted to the role (the group), not to the person; a permission that is no longer needed is removed. Permissions that accumulate because nobody removes them are called privilege creep.

Need-to-know is a second, independent principle: a subject receives access to a piece of information only if the current task requires it, even when the privilege level would technically allow the access. Least privilege limits the level of access; need-to-know limits the scope of the information. Two accountants hold the same level (USE), yet the folder of client A is readable only by the accountant assigned to client A. Need-to-know requires a data classification; at NorthMaple: public, internal, confidential.

Separation of duties completes the two principles: a sensitive operation is divided so that no single identity can complete it alone. The accountant who prepares a payment does not approve it.

The measurable effect: a program never obtains more rights than the account that started it, unless it exploits a vulnerability. The receptionist opens invoice.pdf.exe. When every employee is in every group and is a local administrator, the program reaches 5 folders out of 5. With the role table, it reaches 1 folder out of 5 (FrontDesk). Least privilege therefore reduces directly the impact of phishing, Trojans and ransomware.

How to apply the two principles, in order: start every role at NONE; add the minimum level that the task needs, one cell at a time, with a one-sentence justification; implement the level through a group; use elevation for the duration of the task only, with UAC (User Account Control) on Windows and sudo on Linux; review at fixed intervals. The Canadian Centre for Cyber Security lists the restriction of administrative privileges among its top ten security actions.

Official sites: National Institute of Standards and Technology — https://www.nist.gov/ · NIST (National Institute of Standards and Technology) Computer Security Resource Center — https://csrc.nist.gov/ · Canadian Centre for Cyber Security — https://www.cyber.gc.ca/

B.1.3Digital identities, permissions, and access: users, groups, and roles on Windows and Linux

Two families of identities exist on every machine: user accounts for people and service accounts for programs. Least privilege applies to both.

Concept Windows (local machine) Linux
Where identities are stored SAM (Security Account Manager) database /etc/passwd (accounts), /etc/shadow (password hashes, readable by root only), /etc/group (groups and members)
Unique identifier SID (Security Identifier) UID (User Identifier), and GID (Group Identifier) for groups
Highest-privilege identity Built-in Administrator, group Administrators root, which has UID 0, group sudo on Debian and Ubuntu, group wheel on Fedora and Red Hat
Ordinary users Group Users UID from 1000 upward; system accounts for services are below 1000
Create a user, create a group New-LocalUser, New-LocalGroup useradd -m, groupadd
Add a member Add-LocalGroupMember usermod -aG group user
List the members Get-LocalGroupMember getent group, id
Force a password change at first logon net user name /logonpasswordchg:yes chage -d 0 name

Windows stores permissions with the identifier, not with the name. Renaming an account changes nothing in its permissions. Deleting an account and creating a new one with the same name produces a new identifier that matches no existing permission. In usermod -aG, the option -a is essential: without it, -G replaces the whole list of supplementary groups.

A role is a business function (Accountant). A group is the technical object that implements the role. The rule of every laboratory: permissions are assigned to groups only, never to individual accounts; accounts are placed in groups; there is one group per role. NorthMaple has seven staff members and four role groups (accountants, technicians, reception, itadmins). Nobody works as root: the administrator's own account joins the sudo group.

B.1.4Overview of the processes and tools used to grant, review, and remove access

B.2.1Windows access control: NTFS permissions, sharing, and an introduction to Active Directory

NTFS (New Technology File System) stores a security descriptor with every file and folder. It contains the identifier of the owner, a DACL (Discretionary Access Control List) that lists who may do what, and a SACL (System Access Control List) that lists which access attempts must be recorded in the security log. Each entry of a list is an ACE (Access Control Entry): an identifier (in this course always a group), a type (Allow or Deny), a set of rights and inheritance flags.

The six basic permissions are Full control, Modify, Read & execute, List folder contents, Read and Write. Modify means read, write, execute and delete, without the right to change permissions or to take ownership; those two rights belong to Full control only. The role groups of NorthMaple receive Modify on their own folder; Full control stays with Administrators and with the SYSTEM account.

The five evaluation rules:

  1. Permissions are cumulative across all the groups of the identity.
  2. An explicit Deny entry overrides any Allow entry, from any group.
  3. An explicit entry (set on the object) overrides an inherited entry (received from the parent folder).
  4. An identity that appears in no entry receives no access: this is the implicit deny.
  5. Entries flow from a folder to its files and sub-folders unless inheritance is disabled. In the icacls notation, (OI) means object inherit (files) and (CI) means container inherit (sub-folders).

A folder published on the network with the SMB (Server Message Block) protocol carries a second list, the share permissions (Full control, Change, Read). For an access that comes through the network, the effective access is the more restrictive of the share permissions and the NTFS permissions. The practice of the course: Change for the role group and Full control for Administrators on the share; the fine decisions are made in NTFS.

In the ClientRecords example, inheritance is removed with icacls /inheritance:r, then three explicit entries are added: Administrators with Full control, Accountants with Modify, SYSTEM with Full control. The proof is a test login: a.tremblay creates and deletes a file, while f.haddad and d.kim receive "Access is denied".

Active Directory is covered at awareness level. It is a central directory database hosted on servers called domain controllers; domain accounts are valid on every computer of the domain. Objects are organized in containers named OU (Organizational Unit), and a GPO (Group Policy Object) attached to such a container pushes security policies (password length, lockout, user rights, firewall settings). Authentication uses the Kerberos protocol, with time-limited tickets. LAB_02 uses local accounts, and the same design rule (permissions on groups, users in groups) transfers to a domain without change. Reference documentation: Microsoft Learn.

Official sites: Microsoft Learn — https://learn.microsoft.com/

B.2.2Linux access control: file ownership, permission bits, and the sudo mechanism

Every file and folder carries one owner, one group, and a mode made of permission bits for three classes: the user class (the owner), the group class and others. Each class has three bits: r (read, value 4), w (write, value 2), x (execute, value 1). On a folder, x is the right to enter the folder and reach its entries; r alone lists the names without giving access to them.

Octal notation adds the values per class: rwx = 7, rw- = 6, r-x = 5, r-- = 4, --- = 0. A fourth leading digit carries the special bits: setuid (4), a program runs with the identity of its owner; setgid (2), on a folder new files inherit the group of the folder; sticky bit (1), in a shared folder only the owner of a file may delete it.

Mode Symbolic Used for
2770 drwxrws--- Role folders: owner and group everything, others nothing, new files inherit the group
750 drwxr-x--- Reference folder that a role may read but not write
700 drwx------ Home folders, folder of SSH (Secure Shell) keys
1777 drwxrwxrwt /tmp: everyone writes, only the owner deletes its files
440 -r--r----- Files in /etc/sudoers.d/

The evaluation rule is different from Windows: one class only is tested. If the subject is the owner, the owner bits decide; otherwise, if the subject is a member of the group, the group bits decide; otherwise the others bits decide. There is no cumulation between classes. The root account bypasses the read and write checks.

sudo lets an authorized account run specific commands as another user, normally root, after authenticating with its own password. Every use is written to the authentication log, which is the accounting part of the AAA (Authentication, Authorization, Accounting) model. The rules are in /etc/sudoers and in /etc/sudoers.d/, and they are edited only with visudo, which checks the syntax before saving; a syntax error locks everyone out of sudo. The rule %technicians ALL=(root) /usr/bin/apt update, /usr/bin/apt upgrade lets the members of the group run only the two update commands as root. The keyword NOPASSWD: is never used for a role account in this course.

C.1.1What hardening means

A newly installed operating system is configured for compatibility, not for security. Hardening is the deliberate process that changes this default state: every component that the host does not need for its role is removed, disabled or restricted, and every component that stays is set to its safest working value.

The attack surface of a host is the complete set of points through which an unauthorized person or program can interact with it. It has five parts that can be counted: listening services, accounts, installed software, enabled features and protocols, and configuration values. Because the parts can be counted, hardening can be measured: the count before and the count after are evidence for the manual.

LAB_02 applied least privilege to accounts. LAB_03 applies the parallel principle of least functionality to systems: a host runs only the functions that its role needs. NIST (National Institute of Standards and Technology) names this principle in control CM-7 of Special Publication 800-53.

Action Meaning Example at NorthMaple
Remove Uninstall software that the role does not need Remove the database engine that the installation image left on the file server
Disable Stop a service and prevent it from starting again Disable the printing service on a server that prints nothing
Restrict Keep the function but limit who or what may use it Keep SSH (Secure Shell) but allow it only from the administrator workstation
Update Replace vulnerable versions with corrected ones Install the security updates every week

The role decides. Hardening never means "switch everything off": a public web server must accept ports 80 and 443, a file server must offer its file-sharing port, and a workstation normally needs no inbound connection at all. The zoning table of LAB_01 and the role table of LAB_02 are the two references.

Two working rules protect the laboratory: take a snapshot before the first change, and apply one change at a time, testing the role after each change. A step that breaks the role is reverted and written in the "problems met" section.

The example: sudo ss -tulpn shows eight listening endpoints on FS-01 (ports 22, 445, 139, 111, 5353, 631, 25 and 3306). The role needs only port 445 for the user zone and port 22 for the administrator. Six endpoints are closed; the attack surface falls from 8 to 2, a reduction of 75%.

C.1.2Hardening measures for Windows and Linux hosts

Windows. Accounts: disable Guest and the built-in Administrator, whose names are predictable (the identifier of the built-in Administrator always ends in -500); use the named administrator account of LAB_02; minimum password length 12; lockout threshold 5. net accounts displays the policy. Services: disable Remote Registry, the Xbox services and the print spooler where they are not needed; remove version 1 of the SMB (Server Message Block) protocol, which worms used to spread in 2017. Updates: automatic, and the newest installed update is recent; Get-HotFix lists them, and a host whose newest update is older than thirty days is behind. Security policies: UAC (User Account Control) enabled (registry value EnableLUA = 1), Microsoft Defender real-time protection on (Get-MpComputerStatus), audit logging of logon events.

Linux. Services: systemctl list-units --type=service --state=running lists what runs, sudo ss -tulpn lists what listens, sudo systemctl disable --now <unit> stops a unit and removes it from the boot sequence. Units commonly disabled on a NorthMaple server: avahi-daemon, cups and rpcbind. SSH (Secure Shell) settings in /etc/ssh/sshd_config: PermitRootLogin no, PasswordAuthentication no (only after a working key has been installed for the administrator, otherwise you lock yourself out), MaxAuthTries 3 and X11Forwarding no. sudo sshd -t validates the file before a restart; sudo sshd -T prints the effective configuration, including default values that are not written in the file. Updates: sudo apt update && sudo apt upgrade, and the package unattended-upgrades for automatic security corrections. Accounts: no account with an empty password; unused accounts locked with sudo passwd -l.

The before-and-after method. Every item is tested twice with a command whose output can be captured. C.1.3Monitoring, controlling, and remediating vulnerabilities through simple configuration management

A host that is hardened on Saturday is not necessarily hardened on Monday. Two practices keep it in its hardened state.

Vulnerability management. A vulnerability is a weakness in software, configuration or procedure that an attacker can use against confidentiality, integrity or availability. A publicly known vulnerability receives a CVE (Common Vulnerabilities and Exposures) identifier from the CVE Program and a severity score from 0.0 to 10.0 under the CVSS (Common Vulnerability Scoring System) standard, published by FIRST (Forum of Incident Response and Security Teams). The NVD (National Vulnerability Database) of NIST (National Institute of Standards and Technology) stores both. A patch is the corrected version of the software. The cycle has five stages, repeated every week at NorthMaple:

  1. Discover: know what you have (inventory of hosts, software, versions).
  2. Assess: find which known vulnerabilities apply (apt list --upgradable, Windows Update, a free scanner inside the laboratory only).
  3. Prioritize: severity, and exposure of the host. A service that the Internet can reach is patched before a service that only the administrator workstation can reach. The Known Exploited Vulnerabilities catalogue of CISA (Cybersecurity and Infrastructure Security Agency) lists the vulnerabilities that attackers really use.
  4. Remediate: install the update, change the configuration, disable the component, or add a compensating control (for example a firewall rule) when no patch exists yet.
  5. Verify and document: run the check again and record the result with its date. A remediation that was not verified is an assumption.

Configuration management. The baseline is the written list of approved values (the ten-item checklist is the baseline of NorthMaple). Drift is any difference between the current state of a host and its baseline; it appears when an update resets a value, when a technician changes a setting to debug a problem, or when malware modifies the system. Correction returns the setting to the baseline value, records the event and, when the change was intentional, updates the baseline with a written justification. A small company needs only a script that compares the host with the baseline, started by cron on Linux or by Task Scheduler on Windows, with every result added to a log.

The example: an update reinstalls the printing service on FS-01, and a technician re-enables password login over SSH (Secure Shell) and forgets it. The weekly check of Monday 07:00 prints two DRIFT lines. After a snapshot, the run with --fix corrects them, validates the file with sshd -t before the restart, and the second run shows zero drift. Two numbers summarize the state of the company: the number of drifted items (target: zero) and the age of the oldest missing security update (target: under seven days).

C.2.1Host-based firewalls: what they filter and how they differ from network firewalls

A firewall examines network traffic and allows or blocks it according to a list of rules. A rule reads the header of the packet: source and destination IP (Internet Protocol) address, the protocol, which is TCP (Transmission Control Protocol), UDP (User Datagram Protocol) or ICMP (Internet Control Message Protocol), and, for the first two, source and destination port. On a host, two more properties count. Direction: inbound rules protect the services of the host, outbound rules limit what the host may contact. State: a stateful firewall remembers the connections it allowed, so the reply packets of a connection that the host opened are accepted without an inbound rule.

Network firewall Host-based firewall
Where Between zones: pfSense or OPNsense, LAB_05 Inside the operating system of one host: Windows Defender Firewall, UFW (Uncomplicated Firewall), firewalld
Strength Enforces the zoning table for many hosts with one rule set, managed in one place, independent of the hosts Sees every packet addressed to the host, also from the same zone; can tie a rule to a named program; travels with the host
Limit Sees only the traffic that crosses it; two workstations of the same zone never reach it Must be configured on every host; anyone with administrative rights on the host, including malware, can switch it off

The host firewall is the only layer that stops lateral movement, which is the movement of malware or of an attacker from one compromised host to its neighbours. The two firewalls fail differently, which is defence in depth. The standard default policy for a host is deny inbound, allow outbound. A firewall with "allow inbound" by default is not a control.

In the example of the six packets, the network firewall decides the four packets that cross a zone boundary. It never sees the packet from one workstation to the other; the host firewall of the second workstation drops it. The SSH (Secure Shell) attempt from the accountant's workstation is allowed by zone but dropped by the host firewall of FS-01, which accepts SSH only from the administrator workstation. Two of the three hostile packets are stopped by the host layer alone.

C.2.2Secure configuration of Windows Defender Firewall and a Linux firewall (UFW or firewalld)

The safe order of operations is the same on every host firewall, and it prevents the most common accident, which is locking yourself out of a remote machine:

  1. Work from the console of the virtual machine and take a snapshot.
  2. Write the rules down before typing them.
  3. Create the management rule first: SSH (Secure Shell) or Remote Desktop from the administrator workstation.
  4. Set the default policies: deny inbound, allow outbound.
  5. Add the role rules, each scoped to the smallest source range that needs the service.
  6. Enable the logging of blocked packets, then enable the firewall.
  7. Save the status output as the AFTER evidence.

Windows Defender Firewall keeps three profiles: Domain, Private and Public. All three stay on, with inbound blocked by default. Set-NetFirewallProfile -All -Enabled True -DefaultInboundAction Block -DefaultOutboundAction Allow -LogBlocked True sets this; New-NetFirewallRule with -RemoteAddress creates a scoped rule. Blocked packets are logged in pfirewall.log. Three habits: a prefix (NM-) for every company rule, never a rule "any program from any address", and never disable the firewall to test.

UFW (Uncomplicated Firewall), on Ubuntu and Debian: sudo ufw default deny incoming, sudo ufw default allow outgoing, sudo ufw allow from 192.168.20.12 to any port 22 proto tcp, sudo ufw limit 22/tcp to slow down password guessing, sudo ufw logging on, sudo ufw enable. deny drops the packet silently and the sender sees a timeout; reject answers at once with an error. deny reveals less to a scanner and is the default. Blocked packets are logged in /var/log/ufw.log.

firewalld, on Fedora and the Red Hat family: rules are organized in zones; a rule is written with --permanent and activated with --reload. A rule without --permanent disappears at the next restart of the service.

Scope every rule. "Allow SSH" opens the service to the whole network, including a compromised workstation. "Allow SSH from 192.168.20.12" opens it to one machine.

Official sites: Ubuntu community documentation, UFW (Uncomplicated Firewall) — https://help.ubuntu.com/community/UFW · firewalld — https://firewalld.org/

C.2.3Choosing firewall rules based on the role of the system (workstation versus server)

The method is mechanical: read the role of the host in the two tables, list the inbound services that the role must offer, list who may use each service, and write one rule per pair. Everything else stays under the default deny policy.

A workstation is a client. It opens connections and receives the replies through the stateful mechanism, so its inbound table is nearly empty. One optional rule: remote help from the administrator workstation only, which is Remote Desktop on TCP (Transmission Control Protocol) 3389 for Windows and SSH (Secure Shell) on TCP 22 for Linux. Port 445 and the older NetBIOS (Network Basic Input/Output System) ports 137 to 139 must never be reachable between workstations, because worms and ransomware use them to move.

C.2.4Validating that the rules work as intended

A rule that exists is not a rule that works. The test matrix has one row per test: source (the vantage point), destination and port, expected result (ALLOW or BLOCK), observed result, verdict (PASS or FAIL) and evidence. Every rule produces at least two rows: a positive test from an allowed source and a negative test from a denied source. A rule that is scoped too widely passes every positive test; only the negative test shows the mistake.

Tools that make one connection attempt: Test-NetConnection -ComputerName 192.168.30.10 -Port 445 on Windows, nc -zv 192.168.30.10 445 on Linux, curl -I for a website, and sudo ss -tulpn on the target to confirm that the service listens. nmap is permitted only against your own virtual machines.

Outcome Meaning
Open A service answered. PASS for an expected ALLOW, FAIL for an expected BLOCK.
Refused The host answered at once that nothing listens on the port, or a rule uses reject. The packet reached the host and the firewall did not drop it. For an ALLOW test it usually means that the service is not started.
Timeout No answer. A firewall dropped the packet, or the host is down. It is the correct result for an expected BLOCK with a deny rule.

The strongest evidence of a BLOCK row is the log of the target: DROP lines in pfirewall.log on Windows, [UFW BLOCK] lines in /var/log/ufw.log on Ubuntu, and journalctl -k with --set-log-denied=all on firewalld. In the example, five of the six tests behave as expected. The Remote Desktop test from the administrator returns "refused": the rule is correct, but the service is not started on the workstation. The FAIL row goes into "problems met and fixes", and the matrix is run again.

D.1.1 to D.1.4What an IDS and an IPS are, and the difference between detecting and blocking

An intrusion is any action that violates the security policy of a system or a network. The word covers attempts as well as successes. Intrusion detection is the process of watching events and analysing them for signs of an intrusion. The reference for the vocabulary is Special Publication 800-94 of NIST (National Institute of Standards and Technology). An IDS (Intrusion Detection System) automates this process: it observes, compares with its detection logic and writes an alert. It does not change the traffic; it is passive and out-of-band, because it works on a copy of the traffic. An IPS (Intrusion Prevention System) contains everything an IDS contains and adds a response: drop the packet, reset the connection, or block the source address for a period. To do this before delivery it must be inline. NIST uses the general term IDPS (Intrusion Detection and Prevention System), because most products can run in both modes. Snort and Suricata are such products.

Property Detection mode Prevention mode
Position Out-of-band: a copy from a mirror port or a network tap Inline: the traffic passes through the device
Action on a match Writes an alert; the packet is delivered anyway Writes an alert and drops, resets or blocks
Timing After delivery Before delivery; every packet is delayed by the inspection time
Cost of a false positive An analyst loses time Legitimate business traffic is blocked: an availability incident
Effect of a device failure Loss of visibility only Fail-open keeps the traffic flowing without inspection; fail-closed cuts the link

Four outcomes: a true positive is an alert for a real attack; a false positive is an alert for an event that was not an attack; a false negative is an attack without alert; a true negative is normal traffic without alert. Tuning reduces false positives without creating false negatives, and it is the reason why a new sensor starts in detection mode.

Three detection methods. Signature-based detection compares the data with known patterns (rules): precise for known attacks, blind to an attack that has no rule yet. Anomaly-based detection builds a baseline of normal activity and alerts on strong deviations: it can find unknown attacks, but it needs a learning period, and unusual legitimate activity (the first monthly backup) produces false positives. Stateful protocol analysis compares the behaviour of a protocol with its definition, for example a web request of 40,000 characters. Most products combine the three.

D.2.1 to D.2.5Architecture of network-based and host-based systems

Four components, whatever the product: the sensor (observes a network) or the agent (observes one computer), the management server (receives, stores and correlates the events), the database server, and the console of the analyst.

A NIDS (Network-based Intrusion Detection System) watches the packets of a network segment; a NIPS (Network-based Intrusion Prevention System) does the same inline. The packet goes through six stages:

Stage What happens
1. Capture The network card is in promiscuous mode, so it hands every frame to the sensor. In VirtualBox: "Promiscuous Mode: Allow All".
2. Decode The headers are read layer by layer.
3. Normalisation Fragments and streams are reassembled, so that a rule can match a pattern that an attacker split across several packets.
4. Detection engine Rules, baselines and protocol checks are applied. The variable HOME_NET tells the engine which addresses are "ours".
5. Output Each match is written as an alert: text lines in fast.log, JSON (JavaScript Object Notation) records in eve.json.
6. Response (prevention only) Pass, drop or reject.

Two limits follow. The sensor cannot decode an encrypted payload: for a connection protected by TLS (Transport Layer Security) it sees addresses, ports, sizes, timing and the name of the server, not the content. And it sees only the traffic of the segment to which it is attached.

A HIDS (Host-based Intrusion Detection System) is an agent on one computer; a HIPS (Host-based Intrusion Prevention System) is the same agent with the right to block. Four functions are common: file integrity monitoring, which is a baseline of SHA-256 (Secure Hash Algorithm, 256-bit) hashes that is recomputed at intervals, log analysis, for example five failed logins from one address in a minute or a new administrator account, process and registry monitoring, and rootkit detection. The agent works after decryption and inside the host. Its costs: memory and processor time on every host, installation and updates on every host, an intruder who becomes administrator of the host can stop it, and it sees nothing of the network around the host. Free products: Wazuh and OSSEC; on Linux also auditd and AIDE (Advanced Intrusion Detection Environment).

Two more types: a WIDS (Wireless Intrusion Detection System) watches the radio side of a Wi-Fi network; NBA (Network Behaviour Analysis) watches flow statistics (who talks to whom, how much, how often) and is the natural place for anomaly-based detection. A company that wants both views deploys both kinds and sends all events to one management server.

Official sites: Wazuh — https://wazuh.com/ · OSSEC — https://www.ossec.net/ · VirtualBox — https://www.virtualbox.org/

D.3.1 to D.3.5Where to deploy: network access points and endpoints

One rule decides everything: a network sensor sees only the packets that cross the point where it is attached. A switch forwards a frame only to the port of the destination, so a sensor on an ordinary port receives only its own traffic and the broadcasts.

Position What the sensor sees Mode
P1, outside the firewall Everything the Internet sends, including what the firewall will discard; too many alerts to read Detection only, if at all; never inline
P2, DMZ (Demilitarized Zone) link, just inside the firewall Only the traffic that the firewall allowed into the DMZ; the classic first position Detection first, prevention after tuning
P3, user-zone link Workstations reaching servers and the Internet; lateral movement Detection
P4, server-zone link Everything that reaches the file server and the database; the company data is here Detection, plus host agents on the servers
P5, the firewall itself All four links at once; OPNsense and pfSense include Suricata Detection first, the prevention switch later (LAB_05)

Outside the firewall, the sensor alerts on every scan of the Internet and the analyst learns to ignore the alerts. Just inside, each alert describes a packet that was allowed in and reached a system: fewer alerts, each one meaningful. With one stand-alone sensor, the placement example chooses P4 first and P2 second; with the firewall included, P5 alone covers every flow that must be seen.

Technique Advantages Limits
Mirror port, called SPAN (Switched Port Analyzer) by Cisco No extra hardware; configured in minutes; out-of-band A busy switch drops mirrored frames first; errors are not copied
Network tap, also written TAP (Test Access Point) Complete copy of both directions; a passive tap keeps passing traffic without power Costs money; short interruption to insert it; still out-of-band
Inline The only technique that allows blocking Adds delay; a failure affects the traffic
Promiscuous virtual interface Free; used in the virtual laboratory Must be enabled explicitly; not possible on AWS (Amazon Web Services) or Azure

Host agents are installed in this order: the servers of the server zone (the data is there and they change rarely), then the web server of the DMZ (the most exposed host), then the administrator's workstation (its credentials give access to every system), then the other workstations. Commercial products that add automatic containment to an agent are sold as EDR (Endpoint Detection and Response).

HOME_NET is the setting that beginners get wrong. Rules are written with a direction, for example alert http $EXTERNAL_NET any -> $HOME_NET any. If HOME_NET does not list the ranges of the company, a rule for inbound attacks never matches, or it matches in the wrong direction. It is the first thing to check when a sensor "sees traffic but never alerts".

D.4.1 to D.4.5How these systems implement the CIS Critical Security Controls in active defense

Version 8.1 of the CIS (Center for Internet Security) Controls (June 2024) has 18 controls and 153 safeguards in three Implementation Groups. IG1 (Implementation Group 1) has 56 safeguards and is called essential cyber hygiene; IG2 (Implementation Group 2) adds the safeguards for a company with dedicated staff and sensitive data; IG3 (Implementation Group 3) contains all 153. Each safeguard also carries one function of the NIST (National Institute of Standards and Technology) Cybersecurity Framework 2.0: Govern, Identify, Protect, Detect, Respond or Recover.

The measures of Classes 1 to 6 (zoning, least privilege, hardening, host firewalls) belong to Protect. Active defense, in this course, is the set of measures that operate during an attack: they observe, alert and, where permitted, react. They belong to Detect and Respond. A detection system is a Detect measure. The Center for Internet Security classifies a prevention system as Protect, because dropping a packet is a protective action. The alert review is a Respond activity done by a person. Attacking back is a criminal offence under section 342.1 of the Criminal Code of Canada and is never part of this course.

Control 13, Network Monitoring and Defense, has eleven safeguards. The ones to remember: 13.1 centralize security event alerting; 13.2 deploy a host-based intrusion detection solution; 13.3 deploy a network intrusion detection solution (the sensor of LAB_04); 13.4 filter traffic between network segments (LAB_05); 13.6 collect network traffic flow logs; 13.7 host-based prevention; 13.8 network prevention (the sensor inline with the right to drop); 13.11 tune the alerting thresholds. The neighbouring controls: Control 8 (audit logs: collect 8.2, centralize 8.9, review 8.11), Control 12 (secure network architecture 12.2), Control 1 (inventory, without which HOME_NET cannot be written), Control 10 (malware defences) and Control 17 (incident response).

Control 13 contains no IG1 safeguard. Safeguards 13.2 and 13.3 are IG2; 13.7 and 13.8 are IG3. The hygiene of IG1 (inventory, accounts, patching, audit logs, hardening) must be in place first, because a sensor that watches an unmanaged network produces alerts that nobody can act on. Laurentide Outfitters inc. is an IG1 company by size, but it holds customer and payment data, which is the usual reason to adopt the IG2 detection safeguards. In the coverage example, the highest degree of coverage is kept for each safeguard: two measures that each cover a safeguard partly do not add up to full coverage.

E.1.1 to E.1.6Writing and reading simple rules and alerts

A rule (also called a signature) is one line of text with two instructions: which packets to examine (the header) and what to look for inside them (the options). When both are true for the same packet, the engine performs the action written first.

alert http any any -> 10.10.10.20 80 (msg:"LAB rule 4 - SQL tautology OR 1=1 in a request to the web shop"; flow:to_server,established; http.uri; content:"or 1=1"; nocase; classtype:web-application-attack; sid:1000004; rev:2;)

The header has seven fields, always in this order: action, protocol, source address, source port, direction operator, destination address, destination port. Actions: alert (always, in LAB_04), drop (inline only), pass, reject. Addresses: one address, a network such as 20.20.20.0/24, a variable ($HOME_NET, $EXTERNAL_NET), a list, a negation such as !20.20.10.10, or any. The direction operator -> means one direction only and <> means both directions; <- does not exist. The header is evaluated first, because its comparisons are cheap.

Option Meaning
msg The readable text printed in the alert line.
sid Signature identifier, unique in the whole rule set. Numbers below 1,000,000 are reserved for distributed rule sets; your own rules start at 1,000,000.
rev Revision counter of the rule text, printed in the alert.
classtype Category of the alert, which also assigns its priority (1 is the highest).
content The byte string that must appear; case-sensitive unless nocase follows.
http.uri The content options that follow search only the normalized request address (%20 decoded to a space). It must be written before the content to which it applies.
flow:to_server,established From client to server, inside a connection whose handshake is complete.
itype:8 The message is an echo request (the request of ping).
flags:S The first packet of a new connection: one alert per attempt.

Every option ends with a semicolon; the missing semicolon is the most frequent syntax error. The engine alerts only if every condition is true; otherwise the packet passes silently. Four mistakes make a rule silent: a wrong HOME_NET; a wrong direction or port (a request on port 443 is encrypted and can never match a content rule); a rule that is not loaded (local.rules not listed under rule-files:, no restart after the edit, duplicated identifier); and letter case or encoding (nocase or http.uri missing).

Reading an alert line of fast.log:

09/16/2026-19:20:42.990001 [**] [1:1000004:2] LAB rule 4 - SQL tautology OR 1=1 in a request to the web shop [**] [Classification: Web Application Attack] [Priority: 1] {TCP} 20.20.10.77:44121 -> 10.10.10.20:80

The line gives the timestamp, then [generator:signature:revision] (generator 1 is the rule engine), the message, the classification and the priority, then the protocol and the packet that matched, from source to destination. eve.json holds one JSON (JavaScript Object Notation) object per event with more fields.

Six steps for a first local rule: name the event in one plain sentence; write the narrowest header that still catches it; add one or two options that remove noise; add the bookkeeping options (msg, classtype, sid from 1,000,000, rev:1); save in local.rules, test the syntax with -T, restart and read the "rules loaded" line; validate with safe traffic.

The four rules of LAB_04: 1000001 alerts on an echo request into the company network; 1000002 alerts on an SSH (Secure Shell) connection to the server zone from a machine that is not the administrator workstation; 1000003 alerts on UNION SELECT in a request to the web shop; 1000004 alerts on or 1=1 in a request to the web shop.

E.2.1 to E.2.5Web application security basics: injection attacks and their countermeasures

A web application builds a database command from fixed text written by the developer and data supplied by the user. An injection attack places user data into a command in such a way that the interpreter reads part of the data as instructions. The root cause is that data and code are mixed in one string. The family includes SQL (Structured Query Language) injection, operating-system command injection and XSS (Cross-Site Scripting), where the input becomes part of the page shown to other users. References: category A03:2021 "Injection" of the OWASP (Open Worldwide Application Security Project) Top Ten, entry 89 of CWE (Common Weakness Enumeration), and technique T1190 of MITRE ATT&CK (Adversarial Tactics, Techniques, and Common Knowledge).

The login form example: the vulnerable code glues the user name between two quotation marks. The input ' OR 1=1 -- closes the string early, adds a condition that is always true (a tautology), and turns the closing quotation mark of the developer into a comment. Every account is returned. UNION SELECT appends the result of a second query chosen by the attacker.

Countermeasure Role
Parameterized query (prepared statement) The primary countermeasure. The command is compiled first with a placeholder; the input is bound afterwards as a value only and can never be read as a command.
Allow-list input validation Accept only the expected shape. A complement, never a replacement.
Least privilege for the database account The application reaches only the tables it needs.
Error handling that does not leak Log the database error; show a generic message.
WAF (Web Application Firewall) and patching Extra layers where the code cannot be changed; they reduce exposure and do not repair the vulnerability.

The detection system sees the request in transit. It cannot fix the code, but it reports the attempt, covers what is not fixed yet, shows a campaign early and proves that a fix works. Its three limits: encryption, because on HTTPS (Hypertext Transfer Protocol Secure) it sees only encrypted bytes; evasion, with 2=2, comments inside keywords or encoded characters; and false positives, such as a forum post about SQL. Prevention in the code and detection on the network are two layers of one defence, not alternatives.

E.3.1 to E.3.7Validating that a detection system actually detects

Running is not detecting. A running process, an open interface and increasing counters prove nothing about detection. Validation means that a known, harmless event is generated on purpose and the expected alert is looked for in the log. A test is safe when it harms nothing (a ping, one connection attempt, one request with a text fragment) and contained when it goes from one of your virtual machines to another inside your isolated laboratory. The string ' OR 1=1 -- sent to your own web-01 is a test; sent to a website that you do not own, it is an attempt at unauthorized access.

The validation loop: predict (write the expected identifier, or "no alert", before the test), generate (one action from a named machine), observe (sudo tail -f /var/log/suricata/fast.log), compare (expected equals observed gives PASS; the right identifier with the wrong addresses is a FAIL).

Test Action From, to Expected
T1 ping -c 4 10.10.10.20 lab-client to web-01 1000001
T2 ssh 20.20.20.10 lab-client to srv-files 1000002
T3 request with ' OR 1=1 -- lab-client to web-01 1000004
T4 request with ' UNION SELECT id FROM accounts -- lab-client to web-01 1000003
N1 ssh 20.20.20.10 ws-admin to srv-files no alert
N2 search for tent lab-client to web-01 no alert

A negative test is ordinary traffic that must produce no alert; it proves that the rules are specific. The public test page of testmynids.org is safe but not contained, because the request leaves the laboratory; the contained version hosts the same file on your own web server.

When the expected alert does not appear, check in this order: is the rule loaded; does HOME_NET contain the test addresses; is the sensor listening on the interface where the traffic passes; do direction and port match; is the traffic encrypted; was the engine restarted after the edit; was the traffic really generated. Evidence of one test: the command as typed, the fast.log line whose timestamp, identifier and addresses match, and the row of the evidence table. A screenshot of ps proves that the sensor runs, not that it detects.

Case study 01 — Two friendly requests on a Friday afternoon

Most probable answer. The DMZ to Server flow is denied with no exception. If the portal needs data, a copy that contains only what the portal needs is brought to it in a controlled way. The Guest to User flow is denied as well, or it is replaced by one tightly scoped path to one printer and nothing else.

Question 3. Neither person is malicious. Why does the administrator still answer from the zoning table and not from the conversation?

Most probable answer. The zoning table contains every allowed flow with its written justification, and anything that is not in the table is denied. With this rule the answer comes from the design, and not from the person who asked in the most convincing way. A flow that sounds harmless, such as printing, is exactly the kind of flow that gets approved without thought in real companies.

Covers: Chapter C (Classes 5 and 6 — Securing Windows and Linux Hosts), sub-chapters § 1.3 "Monitoring, controlling, and remediating vulnerabilities through simple configuration management" and § 1.4 "Validation of host security configurations using free baseline checklists — CIS (Center for Internet Security) Benchmarks"

Case study 07 — Six packets and six tests

C § 2.1C § 2.3C § 2.4

Covers: Chapter C (Classes 5 and 6 — Securing Windows and Linux Hosts), sub-chapters § 2.1 "Host-based firewalls: what they filter and how they differ from network firewalls", § 2.3 "Choosing firewall rules based on the role of the system (workstation versus server)" and § 2.4 "Validating that the rules work as intended"

Situation. Malware runs on the accountant's workstation WS-WIN-01 (192.168.20.11). It tries to reach the neighbouring workstation on port 445, it tries to reach FS-01 (192.168.30.10) over SSH (Secure Shell) on port 22, and its operator probes FS-01 directly from the Internet. Later, the technician validates the rules from three machines. One test gives a surprise: Remote Desktop from the administrator workstation to WS-WIN-01, expected ALLOW, returns "refused".

Question 1. For each of the three hostile packets, which firewall layer stops it?

Most probable answer. The probe from the Internet is dropped by the network firewall, because no rule of the zoning table allows it. The packet to the neighbouring workstation never crosses a zone boundary, so the network firewall never sees it; the host firewall of the second workstation drops it. The SSH attempt to FS-01 is allowed by zone, but the host firewall of FS-01 accepts port 22 only from the administrator workstation 192.168.20.12 and drops it. Two of the three hostile packets are stopped by the host layer alone.

Question 2. What does this case show about the two kinds of firewall?

Most probable answer. A network firewall sees only the traffic that crosses it. The host firewall sees every packet addressed to the host, also from the same zone, and it is the only layer that stops lateral movement. The two layers fail differently: malware that disables a host firewall still meets the network firewall on its way to another zone, and an attacker who passes the network firewall through an allowed port still meets the host firewall of the target. This is defence in depth.

Question 3. How is the "refused" result read, and what goes into the manual?

Most probable answer. "Refused" means that the packet reached the host and that the host answered at once that nothing listens on the port. The firewall did not drop it, so the rule is correct; the Remote Desktop service is not started. netstat -an on Windows (or ss -tulpn on Linux) confirms it. The row is recorded as FAIL with its cause and its fix in the section "problems met and fixes", the service is started, and the matrix is run again. A timeout would have pointed to a firewall that drops the packet, or to a host that is down.

Case study 08 — The first sensor of Laurentide Outfitters inc.

D § 1.3D § 3.2D § 3.3D § 3.5

Covers: Chapter D (Class 7 — Intrusion Detection and Prevention Systems: deployment), sub-chapters § 1.3 "The difference between detecting and blocking, stated precisely", § 3.2 "The five candidate positions on the Laurentide Outfitters inc. network", § 3.3 "How the copy of the traffic reaches the sensor" and § 3.5 "The setting beginners get wrong: HOME_NET"

Situation. Laurentide Outfitters inc. has one firewall with four links: Internet, DMZ (Demilitarized Zone) with the web shop 10.10.10.20, user zone and server zone. The technician has one sensor machine with Suricata. The owner says: "Put it in front of the firewall, so that we see everything, and make it block attacks from the first day."

Question 1. Where does the technician place the sensor, and why not outside the firewall?

Most probable answer. Just inside the firewall. With one stand-alone sensor, the placement example chooses the server-zone link first (the company data is stored there) and the DMZ link second (the web shop is the most exposed system). Outside the firewall, the sensor alerts on everything the Internet sends, including what the firewall will discard; there are too many alerts and the analyst learns to ignore them. Just inside, each alert concerns a packet that was allowed in and reached a system: fewer alerts, each one meaningful. After LAB_05, the firewall itself, which includes Suricata, covers all four links at once.

Question 2. Why does the sensor start in detection mode, and what would blocking require?

Most probable answer. A new sensor must be tuned. In detection mode, which is out-of-band on a mirror port, a false positive costs a few minutes of an analyst. In prevention mode the same false positive blocks legitimate traffic and takes the web shop offline, which is an availability incident. Blocking requires an inline connection with two interfaces; every packet is delayed by the inspection time, and the company must decide between fail-open (traffic continues without inspection) and fail-closed (the link is cut). The decision table of the class says: detection first, prevention after about two weeks of tuning on the DMZ link.

Question 3. The sensor is installed in VirtualBox. First its counters stay at zero; after a correction the counters increase, but no alert ever appears. Name the two probable causes.

Most probable answer. Counters at zero: the adapter of the sensor is still set to Promiscuous Mode "Deny", so the sensor receives only its own traffic (or it listens on the wrong interface). The correct setting is "Allow All". Counters that increase without any alert: HOME_NET was left at its installation value. The rules are written with a direction ($EXTERNAL_NET any -> $HOME_NET any), so with a wrong value the inbound rules never match. The correct value lists the ranges of the company: 10.10.10.0/24, 20.20.10.0/24 and the server range.

Case study 10 — The alert that did not appear

Covers: Chapter E (Class 8 — Intrusion Detection and Prevention Systems: rules, injection, validation), sub-chapters § 1.4 "How the engine reads a rule — and the four mistakes that make it silent", § 2.4 "Countermeasures — the developer's layer", § 3.2 "Safe and contained — a test is not an attack" and § 3.6 "When the expected alert does not appear — troubleshooting order"

Most probable answer. The request uses HTTPS (Hypertext Transfer Protocol Secure) on port 443. Most probable answer. It is refused. A test is safe when it harms nothing and contained when it stays inside the isolated laboratory, from one of your virtual machines to another. Most probable answer. The alert reports the attempt; it does not repair the application. Injection works because data and code are mixed in one string. Allow-list validation, least privilege for the database account and error messages that do not leak are complements. Prevention in the code and detection on the network are two layers of one defence.

Verification answers "does the control actually work?": it performs a test, for example a root login over SSH (Secure Shell) that must be refused. A complete chapter contains both. An exception is an item that stays FAIL on purpose. It needs a written justification and, when possible, a compensating control. An exception without justification is a gap; with justification it is a decision. For the score, exceptions are removed from the denominator and never counted as passes: eight passes with one exception and one failure give 8 of 9, which is 89%.

Why this answer earns the marks: The two terms are defined with one example each, so the difference is visible. The treatment of the exception is complete: conditions, meaning and arithmetic. The number proves that the student can compute the score and not only recite the rule.

Essay 13C § 2.1

Covers: Chapter C (Classes 5 and 6 — Securing Windows and Linux Hosts), sub-chapter § 2.1 "Host-based firewalls: what they filter and how they differ from network firewalls"

Question. Explain why NorthMaple needs both a network firewall and host-based firewalls.

0 wordsDefinition, then application to the company, then the reason in one sentence.

Hint: Think about two workstations of the same zone, and about what happens when one layer fails.

Model answer: The network firewall stands between the zones and enforces the zoning table for many hosts with one rule set. Its limit: it sees only the traffic that crosses it. Two workstations of the same zone exchange packets through the switch without ever reaching it. The host firewall runs inside each host, sees every packet addressed to that host and is the only layer that stops lateral movement. Its limits: it must be configured on every host, and anyone with administrative rights can switch it off. The two layers fail differently. Malware that disables a host firewall still meets the network firewall; an attacker who passes through an allowed port still meets the host firewall of the target. This is defence in depth.

Why this answer earns the marks: The answer gives the strength and the limit of each layer and shows that each limit is covered by the other layer. It uses the correct term, lateral movement, and ends with the general principle of the course.

Model answer: Work from the console of the virtual machine and take a snapshot. Write the rules down. Essay 15D § 1.3

Covers: Chapter D (Class 7 — Intrusion Detection and Prevention Systems: deployment), sub-chapter § 1.3 "The difference between detecting and blocking, stated precisely"

Question. Explain why a new sensor is started in detection mode and not in prevention mode. Use the terms false positive, tuning, fail-open and fail-closed.

0 wordsDefinition, then application to the company, then the reason in one sentence.

Hint: Compare what the same mistake costs in each mode.

Model answer: The two modes use the same detection logic. In detection mode the sensor works out-of-band on a copy of the traffic; on a match it writes an alert, and the packet is delivered anyway. In prevention mode it is inline and can drop the packet. A false positive is an alert for an event that was not an attack. In detection mode it costs a few minutes of an analyst; in prevention mode it blocks legitimate traffic and can take the web shop offline. Tuning reduces false positives without creating false negatives, and it must be done first. An inline device also needs a decision for the case of failure: fail-open keeps the traffic flowing without inspection, and fail-closed cuts the link.

Why this answer earns the marks: The four required terms are used correctly and connected by one line of reasoning: same logic, different position, different cost of a mistake. The answer is the justification of the decision table of the class, "detection first, prevention after tuning".

Essay 16D § 2.5

Covers: Chapter D (Class 7 — Intrusion Detection and Prevention Systems: deployment), sub-chapter § 2.5 "Network-based versus host-based, side by side"

Question. Compare a network-based sensor with a host-based agent: what does each one see, what can each one not see, and why does a company deploy both?

0 wordsDefinition, then application to the company, then the reason in one sentence.

Hint: Think about encryption, about other segments, and about who can switch each one off.

Model answer: A network-based sensor reads the packets copied from one segment. It adds no load to the protected systems and sees traffic between other hosts when it crosses that segment. It cannot read encrypted payloads, where it sees only addresses, ports, sizes and the server name, and it sees nothing on other segments. A host-based agent reads files, logs, processes and the actions of users on one computer, after decryption. It performs file integrity monitoring, log analysis, process monitoring and rootkit detection. It costs memory and processor time on every host, sees nothing of the network around it, and an intruder who becomes administrator of the host can stop it. A company deploys both and sends all events to one management server, because each one covers the limits of the other.

Why this answer earns the marks: The answer follows the three parts of the question for each type and ends with the combined architecture. The points about encryption and about the administrator who can stop the agent are the two facts that students most often forget.

Question. Explain why an SQL (Structured Query Language) injection works, name the primary countermeasure, and explain why a detection sensor still helps after the code is fixed.

0 wordsDefinition, then application to the company, then the reason in one sentence.

Hint: Data and code. Then: prevention in the code and detection on the network are not alternatives.

Model answer: The application builds a database command from fixed text and from data supplied by the user. When the code glues the input into the command, the interpreter reads part of the input as instructions. With ' OR 1=1 --, the input closes the string, adds a condition that is always true and comments out the rest, so every row is returned. The root cause is that data and code are mixed in one string. The primary countermeasure is the parameterized query: the command is compiled first with a placeholder, and the input is bound afterwards as a value only. The sensor still helps: it reports attempts with time and source, shows a campaign early, covers what is not fixed yet and proves that the fix works. Its limits are encryption, evasion and false positives.

Why this answer earns the marks: The answer gives the mechanism, the root cause in one sentence, the primary countermeasure with the reason why it works, and the four services of the detection layer. Naming the limits shows that the sensor is a second layer and not a replacement of the fix.
